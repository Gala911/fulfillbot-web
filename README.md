# Fulfillbot Web — сравнение фулфилментов (сайт + сервер)

Серверная версия того же инструмента, что и Telegram-бот, только с веб-интерфейсом.
Работает через собственный сервер, поэтому — в отличие от чисто браузерной
версии — реально может ходить на чужие сайты: сканировать цены и пробовать
автоматически отправлять заявки через формы. В базе уже 21 компания по 10+
городам (Москва, Санкт-Петербург, Новосибирск, Казань, Волгоград, Екатеринбург,
Набережные Челны, Уфа и др.), собранных по открытым прайсам на сентябрь 2026.

## Локальный запуск (для проверки перед деплоем)

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Открой в браузере: **http://localhost:5000**

## Деплой на Railway (рекомендуется, бесплатно, ~15 минут)

1. Зайди на **railway.app**, зарегистрируйся (проще всего через GitHub-аккаунт).
2. Если аккаунта на GitHub ещё нет — заведи на **github.com**, создай новый
   репозиторий (кнопка "New repository"), назови как угодно, и через веб-интерфейс
   GitHub ("Add file → Upload files") перетащи туда все файлы из этой папки
   (`app.py`, `database.py`, `seed.py`, `forms.py`, `scraper.py`, `requirements.txt`,
   `Procfile`, и папку `static/`).
3. В Railway: **New Project → Deploy from GitHub repo** → выбери свой репозиторий.
4. Railway сам увидит `requirements.txt` и `Procfile`, установит зависимости
   и запустит сервер — обычно без дополнительной настройки.
5. Через 1-2 минуты Railway выдаст ссылку вида `https://your-app.up.railway.app` —
   это и есть готовый сайт с одной общей базой данных для всех, кто по ней зайдёт.

**Важно про базу данных:** SQLite-файл (`fulfillbot.db`) на бесплатном тарифе
Railway может сброситься при перезапуске сервера (это ограничение бесплатного
уровня, не самого кода) — при перезапуске данные заново заполнятся из `seed.py`
(21 компания), но то, что добавили пользователи вручную, может потеряться.
Если это критично — можно подключить постоянное хранилище (Railway Volumes,
платная опция) или перейти на внешнюю БД (Postgres, тоже есть бесплатный
тариф на Railway).

## Что умеет
- **Сравнение** — таблица тарифов по услуге, с фильтром по городу, отсортирована по цене
- **Компании** — добавление компаний (с указанием города), ручной ввод/обновление тарифов
- **Сканировать сайт** — best-effort поиск цен в тексте страницы компании
  (сервер сам делает запрос к сайту — это возможно только потому, что запрос
  идёт с сервера, а не из браузера пользователя)
- **Заявка** — заполняешь контакты и объём, сервер:
  1. ищет обычную HTML-форму на сайте компании,
  2. показывает предпросмотр, что будет отправлено,
  3. только после твоего подтверждения («Отправить по-настоящему») реально
     отправляет форму

## Честно об ограничениях
- **Не у всех сайтов есть открытые цены** — многие считают тариф только по
  заявке. `Сканировать сайт` в таком случае ничего не найдёт — это норма.
- **Автоотправка работает не везде.** Формы на JS-виджетах (Bitrix24, Tilda,
  amoCRM) сервер не умеет заполнять — только обычные HTML `<form>`. Если не
  получилось, приложение отдаст готовый текст заявки для отправки вручную.
- **Звонить сервер не умеет** — для звонков нужна отдельная интеграция с
  голосовой телефонией (Twilio/Zadarma/Voximplant), это отдельный проект.
- Для Липецка, Нижнего Новгорода и Саратова локальных операторов с открытыми
  числовыми тарифами найти не удалось — там показывается только федеральный
  СДЭК Фулфилмент.
- Перед массовой рассылкой заявок проверь на 1-2 компаниях, что заявка
  реально доходит.

## Структура проекта
```
app.py          — Flask-сервер и REST API
database.py     — SQLite: компании (с городом), тарифы, лог заявок
seed.py         — начальные реальные данные: 21 компания, 10+ городов
scraper.py      — best-effort поиск цен на сайте компании
forms.py        — best-effort автозаполнение и отправка веб-форм заявок
static/index.html — фронтенд (один файл, без сборки, с фильтром по городу)
requirements.txt
Procfile        — команда запуска для Railway/Render
```
